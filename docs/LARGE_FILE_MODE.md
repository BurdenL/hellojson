# 大文件模式：第 1～6 步

已实现性能基线、统一字节数据源、只读分页文本浏览、后台按需树索引及大文件操作，并完成 Windows 压力验收。
打开文件时不全量读取或建立完整树；树视图使用独立的 LargeTreeModel。

## 使用

- 普通“打开”自动判断文件大小：超过 2 MiB 使用大文件模式，其余保留现有编辑模式。
- 文件菜单 → “以大文件模式打开…”（Ctrl+Shift+O）可对任意大小文件手动启用。
- 支持首页、上一页、下一页、末页，以及按从 0 开始的字节位置跳转；
  跳转后光标定位到该位置附近的完整 UTF-8 字符。
- 每页约 64 KiB 原始字节；状态栏显示实际字节区间（左闭右开）、文件总大小和缓存用量。
- 支持跨页 UTF-8 中文和四字节字符、无换行压缩 JSON、超长字符串和 UTF-8 BOM。
- 大文件模式只支持 UTF-8；检测到 UTF-16/32 BOM 时提示转换编码。分页文本不校验 JSON，
  无效 UTF-8 字节可能显示为替代字符，不能用分页显示结果判断文件是否合法。
- 文件大小或修改时间发生变化时停止显示缓存页并提示重新打开。

大文件模式不支持原地编辑和普通“保存”，防止把当前页误当成完整文档保存。
分页文本可以选择和复制；全文搜索、节点导出和格式化到新文件使用专用入口。
小文件原有功能保持可用。

## 按需树视图（第 4 步）

- 展开节点时，后台扫描直接子节点，使用 QTreeView + QAbstractItemModel 的 fetchMore()，
  每批返回最多 64 个子节点。可点击“加载更多”继续当前组。
- 每个容器只保留一组最多 256 个直接子节点。选中容器或其叶子节点，
  使用“上一组子节点 / 下一组子节点”翻组；数组显示真实下标。
- 每页签最多常驻 4096 个节点。达到预算后折叠其他分支即可继续；
  折叠会释放该节点的全部已加载后代。
- 点击“取消扫描”停止任务；“加载更多”重试未完成批次。切换文件或关闭标签后，
  旧结果被丢弃，后台退出后自动删除该页签的临时索引文件。
- 每个批次的偏移和短预览写入自动清理的临时文件，最多缓存 128 批，
  磁盘文件上限 16 MiB。淘汰后访问旧页面会重新扫描，不保证任意位置即时跳转。
- 键名和值只保留最多约 128 字节的预览，保留重复键、原始数字表示和 64 位偏移。
  第 5 步提供完整节点复制/导出以及树与文本互相定位。

树的根节点最初只根据首个有效字节识别类型；根标量也只读取短预览。
这不能证明整个 JSON 有效。展开容器时严格检查已扫描内容，遇到非法输入、
截断或超过 512 层的嵌套会报告字节位置。尚未扫描的后半部分不会提前校验。
若某个直接子节点自身巨大，确定其结束位置仍需流式扫描整个子值；
此时显示进度并允许取消，内存有上限，但耗时随扫描字节数增加。

## 大文件操作（第 5 步）

- **搜索**：Ctrl+F 聚焦大文件搜索框，输入后点击“搜索文件”或回车。
  搜索 UTF-8 原始文本，区分大小写，不解释 JSON 转义，不支持正则表达式。
  例如源文件中的反斜杠 u 转义需要按源文本搜索，不能当成对应汉字搜索。
  关键字限制为 1～4096 个 UTF-8 字节，支持跨读取块匹配与重叠匹配。
- **结果**：后台每 32 条返回一批，每轮最多保留 128 条；从下拉框选择字节位置即可跳转。
  点击“继续搜索”从上轮最后匹配的下一个字节继续，替换当前结果列表。
  本批数量不是全文总匹配数；无结果时也会继续扫描到文件末尾。
- **树 → 文本**：双击节点，或右键选择“在文本中定位节点”，跳到值的起始字节。
- **文本 → 树**：将光标放到目标位置，点击“在树中定位光标”。
  后台扫描尚未索引的内容，显示包含该字节的最深节点；对象键也映射到对应的值节点。
  分隔符、空白可能定位到容器。定位后只保留该条祖先路径，释放先前展开的其他分支；
  当前组从命中的子节点开始，可加载后续子节点或翻到前一组。
  远处位置或巨大嵌套值可能需要较长扫描，可取消，不承诺随机位置瞬时定位。
- **复制 / 导出**：树右键“复制节点 JSON”最多复制 1 MiB 原始节点内容；
  大节点使用“导出节点到文件”。导出按 64 KiB 块写入，不把整个节点放进剪贴板或内存。
  根节点导出包含根值及末尾文本，不额外证明源文件合法。
- **格式化 / 压缩**：大文件面板“文件操作”菜单中选择“格式化到文件…”或“压缩到文件…”。
  流式校验完整 JSON 并输出，保留数字精度、重复键、字段顺序及字符串转义。
  美化使用两空格缩进及 LF 换行，压缩去除字符串外空白；输出不带 UTF-8 BOM。
  超过 512 层嵌套、非法语法或 I/O 失败均中止输出。
- **取消与文件保护**：点击“取消任务”；打开其他文件或关闭标签也会取消旧任务。
  使用 QSaveFile 写临时文件，成功后才提交，取消或失败时删除未完成输出并保留已有目标。
  禁止选择源文件本身作为输出。作业开始及读取期间检查源文件大小/修改时间，
  发生变化后要求重新打开。正在执行的系统 I/O 或已经完成的提交无法撤回。

每页签一次执行一项搜索、定位或写出任务；它们与文本分页、树展开使用独立线程，
操作过程中仍可翻看文本和取消任务。搜索结果与路径都受数量上限约束。

## 数据与线程

- JsonDataSource：64 位字节位置、大小和有上限的读取接口。
- MemoryJsonSource：内存实现；FileJsonSource：文件实现，固定 64 KiB 块、8 块 LRU 缓存。
  小文件加载也通过数据源读取，并在加载前检查编辑模式大小上限。
- 单次源读取上限 1 MiB；文本、树扫描、当前操作各使用独立的 512 KiB 文件数据缓存，
  合计每页签最多 1.5 MiB，操作完成后释放操作数据源。跨 UTF-8 页边界最多额外检查 3 字节。
- PageReader 在独立线程打开和读取文件；界面仅接收当前页的解码文本，不启用语法高亮或撤销历史。
- 新请求淘汰旧请求的结果；关闭页面不等待存储 I/O，后台对象完成当前有界读取后释放文件和缓存。
- QTextDocument 和渲染缓存仍占用额外内存，但只对应一页，不随文件总大小增长。
  多个大文件页签的开销仍会累加。操作系统文件缓存不计入应用的 512 KiB 数据缓存预算。
- 树工作线程以 64 KiB 块读取，并在约每 4096 字节检查取消；正在执行的系统文件读取
  不能被立即中断。视图只接收有上限的节点批次，不接收整个源文件或完整 JSON DOM。

## 验收标准

本阶段采用以下测试目标，而不是对任意硬件和存储的耗时承诺：

1. 1 GiB 测试文件只读首屏、首尾跳转及 16 次分散跳转成功。
2. 每个文件数据源缓存始终不超过 512 KiB；每页文本不超过 64 KiB + 3 字节的解码结果。
3. 测试进程峰值工作集小于 512 MiB，且同形状 8 MiB → 1 GiB 文件不呈线性内存增长。
4. 本机生成文件的首屏和单次翻页目标小于 500 ms；Qt 界面事件循环最大间隔小于 500 ms。
5. 页边界拼接无 UTF-8 字符丢失、重复或替代；格式化不全量载入内存，当前页不能误当成整篇保存。

## 第 1～3 步实测基线（接入树视图前）

2026-09-20，本机 Windows 11、MSVC、Qt 6.11.1 Debug，1200×780 离屏界面，
加载中文字体。每项使用独立进程；文件为实际写入的生成数据，不是稀疏文件。
测试运行前刚生成文件，因此存储可能命中操作系统缓存，不代表冷盘读取表现。

| 路径 / 数据 | 文件大小 | 首屏 ms | 最慢跳转 ms | 峰值工作集 MiB | 结束时私有内存 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧全量加载 / 数组 | 1 MiB | 838 | — | 60.7 | 26.3 |
| 旧全量加载 / 数组 | 8 MiB | 7093 | — | 187.2 | 142.4 |
| 分页 / 数组 | 8 MiB | 69 | 63 | 49.0 | 12.2 |
| 分页 / 数组 | 1 GiB | 60 | 60 | 49.0 | 12.3 |
| 分页 / 嵌套对象、无换行 | 8 MiB | 222 | 205 | 48.6 | 11.0 |
| 分页 / 单个超长字符串 | 8 MiB | 382 | 380 | 49.5 | 11.2 |
| 分页 / 单个超长字符串 | 1 GiB | 393 | 373 | 49.7 | 11.0 |

每项分页测试包含首屏及 16 次分散跳转，共读入约 2.88 MiB 文件数据，
最终源缓存为 512 KiB。两项 1 GiB 测试最大事件循环间隔分别为 85 ms 和 323 ms。
工作集含共享 DLL、字体及渲染资源；私有内存是结束时快照，不能当成峰值私有内存。

“旧全量加载”在基准程序中复现 QTextStream.readAll → JsonTab.setText 的打开流程，
包含编辑器和语法高亮，不包含格式化/树解析。为避免主动耗尽内存，仅允许基线文件
不超过 8 MiB，没有用旧路径打开 1 GiB 文件。不能据此线性推算旧路径的 1 GiB 精确峰值。
完整原始数据见 [large-file-benchmark.json](large-file-benchmark.json)。

## 第 4 步实测

同日、同一 Windows / Qt Debug 离屏环境，使用实际写入的文件，独立进程运行。
数组测试在文本首屏和 16 次分散跳转后，连续浏览 20 组树节点（每组 256 个），
再回翻一组并折叠根节点。数据刚生成，可能命中操作系统缓存。

| 数据 | 文件大小 | 首屏 ms | 最慢文本跳转 ms | 最慢树分页 ms | 峰值工作集 MiB | 结束私有内存 MiB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 数组 + 按需树 | 8 MiB | 71 | 60 | 90 | 51.1 | 13.7 |
| 数组 + 按需树 | 1 GiB | 71 | 61 | 88 | 51.2 | 13.7 |
| 超长根字符串 + 根预览 | 1 GiB | 374 | 353 | — | 50.4 | 12.0 |

两项数组测试临时索引均为 275,300 字节，回翻命中缓存，折叠后只剩 1 个根节点。
最大界面事件循环间隔分别为 72 / 73 ms；超长字符串为 323 ms。
文件大小从 8 MiB 增至 1 GiB 时，本组相同操作下没有观察到按文件大小线性增长的进程内存。
这些数据不表示扫描任意巨大子值也能在 88 ms 内结束。
原始报告见 [large-tree-benchmark.json](large-tree-benchmark.json)；
报告中的 cached_file_bytes / disk_bytes_read 是文本数据源统计，树磁盘索引另列于 tree。

## 第 5 步操作实测

2026-09-20，同一 Windows / Qt 6.11.1 Debug 离屏环境，以独立进程运行。
每次先完成分页打开和 16 次文本跳转，再全文搜索不存在的关键字、定位约 1.25 MiB
处的节点、导出整个根节点、完整格式化，最后压缩刚生成的格式化文件。
源文件为刚写入的实际数据，可能命中操作系统缓存；1 GiB 测量期间同机还运行了构建和回归测试。

| 原始数组大小 | 全文搜索 s | 根节点导出 s | 格式化 s | 压缩格式化结果 s | 峰值工作集 MiB | 最大事件循环间隔 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 100 MiB | 0.123 | 0.189 | 16.857 | 14.785 | 51.6 | 93 |
| 1 GiB | 1.287 | 1.687 | 171.218 | 150.486 | 51.6 | 254 |

两次定位耗时约 116 / 115 ms，目标均在文件前部；不能据此推断任意远处节点的定位耗时。
格式化和压缩已处理完整输入并成功提交输出，没有使用提前取消来代替完成测试。
同样操作下，内存没有随文件大小线性增长；耗时随扫描字节数增加。

## 重现

在配置好 MSVC/Qt 的 Developer PowerShell 中，构建测试目标：

    cmake --build out/build/debug --parallel 4
    ctest --test-dir out/build/debug --output-on-failure
    python tests/generate_large_json.py out/fixtures/array-1g.json --mib 1024
    python tests/generate_large_json.py out/fixtures/string-1g.json --mib 1024 --shape string

将 QT_QPA_PLATFORM 设为 offscreen，QT_QPA_PLATFORM_PLUGIN_PATH 设为当前 Qt kit
的 plugins/platforms，并确保 Qt DLL 可被加载，然后运行：

    out/build/debug/hellojson_benchmark.exe paged out/fixtures/array-1g.json out/paged-1g.json

legacy 参数运行受 8 MiB 上限保护的旧路径；paged 参数强制使用大文件模式。
tree 参数额外展开大数组并连续浏览 20 组子节点、回翻和折叠，输出树索引统计：

    out/build/debug/hellojson_benchmark.exe tree out/fixtures/array-1g.json out/tree-1g.json

tasks 参数运行上述完整操作链，自动清理成功生成的测试输出，保留测量报告：

    out/build/debug/hellojson_benchmark.exe tasks out/fixtures/array-1g.json out/tasks-1g.json

还可用 --shape nested 生成嵌套对象测试文件。每份报告记录大小、首屏/跳转耗时、
事件循环间隔、内存、缓存和实际读入字节数。生成文件位于忽略的 out 目录，可在测量后清理。

Qt Test 覆盖 UTF-8 所有跨页字节位置、BOM、空文件、整页边界、CRLF、超长字符串、
缓存上限与命中、64 位位置、文件变更、连续异步请求、自动/手动模式、禁用操作及小文件回归。
新增树测试覆盖模型契约、分批加载、子节点翻组、折叠释放、常驻节点上限、取消及过期结果、
临时索引关闭清理、128 批缓存淘汰与 16 MiB 文件轮换、UTF-8、非法输入和深度限制。
第 5 步另覆盖跨块及重叠搜索、结果分页、非驻留节点定位、CRLF 光标映射、无损格式化、
非法 JSON 不覆盖目标、写入故障、复制上限、导出、文件变化和取消/关闭时的临时输出清理。

## 第 6 步压力验收与交付

2026-09-21，Windows、Qt 6.11.1、MSVC x64 Release，1200×780 离屏界面。
实际生成 100 MiB / 1 GiB 文件，非稀疏文件；测试可能命中操作系统缓存。
Debug 和 Release 均通过 128 项 Qt Test，包括小文件编辑、格式化、搜索、
大小文件模式连续切换，以及 511 / 512 / 513 / 2048 层深度边界。
修复了按需树扫描子值时重新从零计算深度的问题，树扫描与格式化现在统一限制 512 层。

多标签场景每组运行 3 轮，每轮 8 标签、每标签 4 次分散跳转，包含切换标签、
搜索、树分页、展开与折叠；关闭前启动真实格式化作业，等待写入进度后关闭全部标签。
每组直接跟踪 72 个工作线程对象，确认退出并销毁，同时确认临时索引和未完成输出被删除。
进程总线程数包含 Qt / Windows 共享线程，因此不以它代替应用线程的生命周期检查。

| 数据 | 大小 | 峰值工作集 MiB | 最慢翻页 ms | 最大事件循环间隔 ms | 关闭清理最大 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 数组 | 100 MiB | 55.1 | 10 | 25 | 32 |
| 数组 | 1 GiB | 53.1 | 55 | 47 | 32 |
| 嵌套对象 | 1 GiB | 50.8 | 27 | 27 | 31 |
| 超长字符串 | 1 GiB | 49.5 | 76 | 153 | 31 |

8 标签文本缓存合计最多 4 MiB；各轮关闭后私有内存约 11～16 MiB，
未观察到逐轮累积，句柄数稳定。验收检查关闭后相对第一轮私有内存增长小于 16 MiB、
句柄增长不超过 16；缓存仍按标签独立分配，并非全应用统一配额。

异常输入覆盖 100 MiB 末尾非法字符、1 GiB 截断文件、1 GiB 超过深度限制的文件。
三项均报告错误、保留既有目标文件并删除临时输出，峰值工作集约 31～2 MiB。
此外对 100 MiB 和 1 GiB 数组完成全文搜索、定位、完整导出、格式化与压缩。
原始数据及完整操作耗时见 [large-file-acceptance.json](large-file-acceptance.json)。

一键重现全部 9 组压力场景（先构建 Release 测试目标）：

```powershell
./tests/run_large_file_acceptance.ps1 -BuildDir out/build/release -QtPlugins '<Qt kit>/plugins'
```

报告默认写入 out/acceptance，生成的测试文件完成后自动删除；使用 -KeepFixtures 保留。
需要数 GiB 可用磁盘空间容纳格式化中间结果。stress 模式验证多标签资源释放，
fault 模式验证异常文件和目标保护，tasks 模式完成全部流式操作。
性能目标针对本机测试，不承诺其他硬件、冷盘或网络存储的响应时间。
